# V2 开发规则、禁止事项与作用域保护

维护基线：2026-09-09。用于本仓库开发；当前用户的明确范围与授权优先。本文件不授予远程写入或正式发布权限。

## 依据与开发边界

- 官方 JS/CSS/图标和协议是复刻依据；以仓库根目录的固定资产 manifest 确定本次基线，不随线上变化无边界扩展目标。
- 当前路线为纯 Flutter UI + Dart 业务 + Kotlin 系统接口。旧 Web 宿主、旧语音/更新模块的历史存在不代表 V2 已迁移完成。
- 修改前核对 `git status`、相关文件与验收记录，保留其他工作；共享根因在共享组件/状态层修复，不逐页复制补丁。
- 当前业务状态沿用 ChangeNotifier/ValueNotifier；协议层无 Flutter 依赖。平台识别使用条件导入，Android 系统能力使用 MethodChannel。
- 注释保留真实官方函数/字段出处。未确认的方法、字段或远控门控先取证，不用猜测填实现。
- 普通已授权的读取、可逆修复、测试和构建直接推进；暂停/整理要求应被保留。提交、推送、打标签和正式发布按当前明确范围执行，不因阶段包生成自动触发。

## 作用域与异步契约

| 数据/操作 | 必须区分的身份 | 常见失效条件 |
| --- | --- | --- |
| 连接、bridge、RPC | 设备/transport、工作区、连接代次 | 断线、换栈、重新认证、释放 |
| 输入、配置、附件、队列 | 设备、工作区、会话；首发暂存身份 | 切会话、首发提升、取消、进程中断 |
| 阅读、展开、面板 | 设备、工作区、会话、主辅面板；日志代次/消息 ID | 新日志、分页迟到、宽度变化、移除设备 |
| 套餐/重置 | transport、供应商、组织、项目、认证代次 | 换账户/来源、恢复连接、页面不可见 |
| 使用统计 | 来源、范围、IANA 时区；应用累计另存 | 切范围、切套餐、重连、时区读取失败 |

实施要求：

1. 请求开始捕获身份/代次，在响应写入前再校验；`mounted` 只能证明组件存在，不能证明来源没变。
2. 每条异步链明确 pending 去重、取消、错误、重试和 dispose 行为。被移除的设备不能被晚到选取器/恢复读取重新创建。
3. 缓存键包含真实维度；切换时立即清除不属于新来源的展示，旧响应最多更新自己的缓存。
4. 同来源多视图可共享请求/幂等状态，不跨设备复用。不要仅凭相同 task ID、provider 名字或 UI 别名合并。
5. 状态推送与列表读取需判断新旧。成员列表记录起始修订号，拒绝在更新后返回的旧读取；不要永远偏向一个来源，也不要简单按响应到达顺序覆盖。
6. 历史按 logEpoch 与请求游标校验；恢复优先消息 ID + 可见偏移，不只存绝对像素。用户真实滚动才改变跟随状态。
7. 发送结果不确定保留输入并核对；本地保存失败、远程接收成功和远程失败是不同状态，不能统一当作可安全重发。

## 凭据与真实远端

- 真实 `sid/hash` 属设备凭据，只允许安全运行时注入和已有加密存储。禁止写入源码、测试、日志、截图名称、文档、剪贴板演示或可复用脚本；合成 fixture 使用明确的假值。
- 原始链接不要回显到命令输出或浏览器地址栏截图；读取日志/DOM 时先做脱敏。不得打印签名私钥、密码或环境变量全集。
- 真实远端默认只读。自动化发送、停止任务、终端命令、删除、配置更改及额度写操作使用合成服务。当前任务另有明确授权时按授权范围执行，不重复索要同一许可。
- 同一个远端同时只由一个本轮客户端持有连接。官方页面/探针前保存对应应用的任务、阅读、主题和字号，释放其连接；完成后关闭浏览器/探针再恢复。另一台连接不同远端的设备可继续运行。
- 名称不能代替身份确认：核对运行时设备身份、已保存链接对应机器及数据作用域。地址或标签变化先重新确认，不反复重连抢占。
- 本轮验收分配为手机 ALI、平板 ROG-STRIX；这是当前任务约定。后续任务改变分配时按新约定，不把端口和当前任务永久写死。
- 发现共享模拟器自行切页时，先判断是否由用户操作；保存交回时的最新任务，不擅自恢复过时的测试起点。

### 额度只读模式的准确含义

`.dev` / `.qa` 可在冷启动 Intent 中设置 `quotaReadOnlyAudit=true`，产品显示角标。它阻止 `requestCodingPlanResetOpportunity`、`useCodingPlanReset`、`markCodingPlanResetHistoryRead`，保留读取。

**这不是全应用只读沙箱**：其他任务、配置、终端等写操作仍须遵守授权边界。普通启动启用自动额度维护；重复启动已运行 Activity 不保证重新初始化该标志。按测试流程先 force-stop 指定包再启动，不能清数据。

## 禁止破坏的产品行为

- 禁止首发重复创建/发送；等待健康超时或回执超时不自动补发；额度重置已受理但未确认时只查询状态。
- 禁止配置失败却展示成功；后续发送使用已确认配置，失败草稿与附件保留。
- 禁止空快照抹掉独立来源、旧响应写入新账户/新会话、旧投影确认新完成。
- 禁止混用上下文字符占比、套餐余额、MCP 额度；缺失数字/日期不伪造 0%、100% 或 1970 年。
- 禁止把应用累计与 7/30 天当一份数据，或共用应用与套餐页的范围选择。
- 禁止用页面总宽替代 Composer 容器宽、用“接近底部”自动重启跟随、用固定颜色忽略主题。
- 禁止用无行为按钮、测试数量或 APK 数量表示功能完成。桌面专属能力按真实远控门控排除，不能借门控删掉仍适用的必需功能。
- 禁止删除已有未提交工作、盲目 `git reset --hard` / `git clean`，或用清除 `.dev` 数据解决测试问题。
- 禁止把集成测试/诊断入口作为产品 APK，或覆盖已冻结阶段的不同源码/产物。

## 验收与外部条件

状态区分：待核查、待实现、已实现待验证、验收通过、受阻、有依据的不适用。每项保留需求、依据、文件、剩余差距、步骤/预期、真实结果、证据位置与构建身份。

合成测试覆盖危险写操作与稀有时序；实际 Flutter 渲染检查布局；真实官方同态对照证明视觉；覆盖安装及实际关键流程证明平台可用。这几类证据不能互相替代。

真实 Start/团队数据、实际录音链路、ColorOS 16 真机组合等条件不足时，说明最小缺失条件并继续独立工作。不能把未实现功能包装成平台限制，也不能用 MuMu API 32 回退结果代替 Android 16 真机验收。
