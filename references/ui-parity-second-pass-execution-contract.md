## 0. 本轮核心要求

目标是让实际安装运行的产品在相同条件下符合官方页面结构、尺寸、资源、文案、状态和操作流程，并满足用户明确提出的 Android 本地扩展要求。

以下均不能当作完成：代码存在；页面能打开；按钮文字相同；控件单测通过；有一张截图；测试很多；上一轮说 PASS；某个入口正常但其他入口不正常；截图对应源码与安装包不一致。

本轮不允许再把“引导”做成导入弹窗、把审查做成直接在聊天展开 Diff、把设置右侧压在窄列里，随后以已有功能或历史验收解释差距。

同时必须基于事实修复：现有代码已经有语音进度、部分中文翻译、审查/撤销和模型测试按钮。先重现失效路径、保留有效成果，再补缺口，不能重写一套平行实现。

## 3. 官方基线与 1:1 的判定

官方事实取自对应版本的实际页面、DOM/布局数据、JS/CSS、i18n、图标/字体/图片和协议。固定资产是可复现基线；用户反馈指向不同官方版本时，先记录版本差异，再把有关页面基线更新范围写清楚，不混合不同版本拼装 UI。

每个关键流程都建立三方对照：官方原图、修复后产品原图、标注差异/叠加对照。原图保留可复查，不靠裁切或缩放隐藏缺陷。

配对必须记录：来源、账户/套餐上下文、工作区、任务、回合/文件、内容状态、滚动位置、主题、语言、系统缩放、UI/代码字号、有效逻辑宽度、辅助面板和键盘状态。物理截图像素不同，不代表可用逻辑宽度相同。

几何表至少记录外壳、导航、顶栏、右侧区、正文列、弹窗、列表和操作按钮的 x/y/w/h、padding、gap、圆角、边框、字号、行高和图标尺寸。实现前按官方实测值登记本轮容差，不能事后扩大容差解释失败。

同等条件下结构、顺序、文案、图标、可见状态和点击流程必须一致。字体抗锯齿与平台栅格化差异可以单列；不能用它们解释错位、宽度、边框、错误图标、缺少按钮或不同交互。

动画、滑入、过渡和下载进度必须用连续帧/录屏证明；两张静态图不能证明流畅。没有官方同状态证据的条目标为“已实现待官方同态验证”，不标 1:1 通过。

检查 `UsagePage`、`ComposerUsage`、`UsageStatistics`、套餐选择读取和设置入口。重点复现：source=null+读取失败；当前模型是第三方但另有有效个人套餐；进入设置后没有已激活会话；切来源后旧响应返回；认证或重连后缓存失效。

## 7. U21/U22 — 审查和撤销完整流程

目标路径：修改回合完成 → 文件变更摘要/审查入口 → 文件列表 → 点击一个文件 → 右侧打开该文件红绿 Diff → 切换文件/返回列表/关闭。

展开摘要只呈现文件列表和该层应有的操作，不默认选中首项并在聊天里展开整段 Diff。点击文件与点击“审查”必须到同一正确入口，不保留两套语义不同的实现。

保留 U05 的工具调用内联 Diff：它用于单次编辑工具内容，与回合审查入口分开。删除错误的摘要自动展开，不得把所有工具内联差异一并删掉。

右侧详情需有文件标题/路径、列表选中状态、关闭/返回、加载、错误、重试；覆盖新增、删除、重命名、二进制、空 Diff、大文件、裁剪、按需内容和分页。回合变更不能用工作区当前总 diff 代替。

逐入口检查 `changeSummary` 生成/解析、`actions.canRewindFiles`、running/reverted 状态、历史回放、订阅增量、`FileChangesReviewHost` 接线及窄屏回退。现有实现和历史截图不能否定当前缺失反馈。

修改后可审查、可撤销的场景必须在官方对应位置提供明确入口。暂不可执行时按真实门控展示禁用原因或规定状态，不做无行为按钮，不私自绕过能力检查。

撤销按官方语义实现：预检 → 列出范围/冲突/不能处理的文件 → 明确确认 → 单次提交 → 等待确认/查询结果 → 更新摘要及 Diff。核查是否仅撤销文件或还有会话影响，不能自行调用 `git reset` 代替。

用可控服务验证失败不假成功、重复点击不重复写、超时后状态未知不盲目补发、旧回合/旧来源响应不能覆盖当前页面。真实远端只读核对，撤销写操作使用独立 QA。

通过条件：单文件/多文件、实时完成/历史/重连、主/辅会话、手机/平板都有完整连续流程；屏幕录像证明先列表后右侧详情；自动测试实际点击产品入口，不只测试独立 Diff widget。

## 10. U25 — 语音下载完整反馈

下载前显示可信模型包大小，必要时区分下载体积和安装后体积。大小来自官方资产元数据或可靠响应；没有可信值显示未知，不硬编码推测 MB。

下载中显示已下载/总大小、百分比和连续变化的进度条。总量未知时显示已下载字节和不确定型动态进度，不永久卡 0%，不造百分比。

建立状态：准备、下载、解压、校验、可用、失败、取消。下载完成 100% 不等于模型已可用；解压与校验阶段有明确反馈。同步解压/校验和通知处理不得阻塞 UI，按连续帧与耗时证据决定移出 UI isolate。

检查现有 `VoiceModelEvents` → 页面 `_refresh` 全目录读取链路；进度通知不能让高频 IO/代次淘汰造成显示更新饥饿。适当节流，但要及时呈现进度和终态。

复用已有进度组件和下载服务，明确运行中任务的所有者。退出再进入页面能够恢复正在进行的状态；同模型重复点击不重复下载；多模型彼此隔离。

通过条件：已知 Content-Length 多段流、未知总长、断网/错误响应、取消/重试、解压耗时、校验失败、退出重进、切模型。验证实际可见的大小/百分比和连续帧，不能只断言 fake map 里有 0.5。回归真实麦克风、预览、停止、取消以及识别只追加草稿不自动发送。

## 11. U26 — 通知与上岛内嵌

点击设置左栏“通知与上岛”后，其主体直接呈现在设置右侧内容区，侧栏保持。删除“先进入设置项，再点 ListTile 跳新页”的二次导航。

抽取/复用 `NotificationSettingsPage` 主体，支持 embedded，不复制整个 controller 或另起不一致状态。避免嵌套 Scaffold/AppBar 产生重复标题、重复 padding 或返回栈。

这是用户明确要求的 Android 客户端扩展，视觉遵守共享设置规范，不宣称官方 Web 有相同系统能力。

保持通知权限、任务进度、前台服务、系统设置跳转与上岛行为。跳系统设置返回后刷新真实状态；设备/来源隔离不退化。窄屏保留清晰导航。

## 13. 验证策略

协议/状态缺陷先补能在旧实现失败、修复后通过的回归；UI 缺陷覆盖真实页面入口、父布局和连续交互。不要只测试 mock 数据或孤立控件，也不要为简单样式写一堆重复实现的断言。

每批运行相关 format/static/targeted tests，阶段末运行合理联合集合；没有新增疑点不反复全量构建。最终候选必须执行 `flutter analyze`、完整 `flutter test`、现有 protocol smoke、必要 Android 编译/原生回归和安装后验收。

关键矩阵包含：手机、平板横竖屏、可用折叠环境；深浅主题；中英文；100%/140% 与系统缩放；主辅面板；键盘；loading/empty/error；两设备/两来源；冷启动/恢复；旧响应迟到。

每一 U 项至少有代表性成功与错误路径。共享布局和状态改动覆盖所有直接受影响组合；完整矩阵仍以现行契约为准，不能拿一张手机截图替代宽屏问题。

## 14. 工程与作用域约束

协议层纯 Dart，现有状态体系继续沿用；Flutter UI 与 Android 系统接口分层。Agent、模型供应商、套餐来源是不同维度。

任何异步操作捕获 device/transport、workspace、conversation/turn、provider/organization/project、source、认证代次和相关 revision，提交结果前复核。mounted 不足以证明身份未变。

不重复发送、不重复撤销、不重复导入、不重复下载；未确认结果不能当失败可重发。配置失败保留已确认状态和编辑草稿。恢复后旧来源不能更新新页面。

保护未提交修改和已有冻结包，不用 reset/clean 覆盖未知工作，不清 `.dev` 数据。独立 QA 使用 `.qa`；不要用集成测试入口作为产品包。

真实远控链接与凭据只经安全运行时/已有加密存储取得，不复制旧 Prompt 的 sid/hash/配对 URL 到代码、文档、截图名、日志或可复用脚本。读取旧文档时对输出脱敏。

真实远端按已有授权只读取证；发送/停止真实任务、终端命令、配置修改、删除、撤销、迁移和额度写入的自动测试用可控服务。quotaReadOnlyAudit 只保护指定额度写 RPC，不是全应用只读沙箱。

正常已授权的代码修改、测试、构建、文档和可逆验收持续执行。真正超出当前授权的真实写入或正式发布，先完成全部本地可验证工作，再在具体边界提出明确请求；不重复要求已有授权。

操作官方/产品同一远端时遵守单连接持有规则，避免互踢影响取证。切换前保存页面状态，结束后释放探针/浏览器连接并恢复合适状态。
