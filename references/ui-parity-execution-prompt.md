# ZcodeRemote 官方界面对齐与交互修复提示词：Luna 实施，主代理验收

使用方式：把下方“执行提示词”整段交给当前主代理；由主代理调用 GPT-5.6 Luna 子代理实施，再亲自复核验收。共 16 项要求，默认每轮完成一个小批次，后续使用文末的续接提示词。首次引用的截图已保存在 `references/assets/turn-change-summary-reference.png`。本文是供后续执行的提示词，本次编写不代表已修复产品或已启动子代理。

## 执行提示词

请在当前 ZcodeRemote 仓库中，依据官方 ZCode 远控界面，修复下列交互、布局和功能差异。中文沟通，直接完成本轮选定批次的取证、实现和验证。

### 目标与本轮范围

目标是让实际使用路径、视觉状态与功能行为符合下列要求。先对全部问题做一次轻量盘点，随后每轮只深入完成一个模块中通常 1–3 项关联问题；共同根因需要一起修改时可合并。语音卡顿和断线无感知/恢复问题为最高优先级，其次处理会话导航与侧栏，再处理 diff、输入菜单、工作面板和设置。已有有效证据通过的项目直接复用。

本轮范围默认：从清单中选择优先级最高且具备实施条件的一组。批次验证和记录完成后结束本轮，交代下一组；不要自行开启无限循环、定时巡检或重复全仓审计。

### 分工、模型调用与费用控制

我明确授权你在执行本提示词时调用 **GPT-5.6 Luna（模型 ID：`gpt-5.6-luna`）作为实施子代理**。你保留当前主代理模型，负责范围、关键方案、独立复核和最终验收。

- 默认每批启动 1 个 Luna，推理档 `medium`；明确简单的文案/样式任务可用 `low`。最多同时 2 个 Luna，只有子任务可独立完成、写入文件互不重叠且有明确收益时才并行。子代理不得继续派生子代理。
- 必须通过实际子代理工具指定模型，不把“你是 Luna”当作模型切换。不使用创建独立用户任务的工具替代子代理，也不更改全局模型配置。先核对当前工具支持的模型与字段；启动后记录子代理 ID、指定的模型/推理档及工具实际确认的信息。工具未返回的实际模型信息标为不可核实，不能虚报。
- 若当前工具为 `collaboration.spawn_agent`，使用显式 `model: "gpt-5.6-luna"`、`reasoning_effort: "medium"`、`fork_turns: "none"`，配合具体 `task_name` 和自包含的 `message`。该工具的完整历史继承方式不能同时覆盖模型，因此不要用 `fork_turns: "all"`。其他运行环境按其实际 schema 配置，不生搬字段。
- 模型或工具不可用时，报告具体失败，不静默换成其他模型。继续主代理能完成的取证与范围整理，等待明确的替代模型决定；不循环尝试同一失败调用。
- 主代理先确定一个可独立实施的边界，给 Luna 一份简短任务包：仓库绝对路径、适用规则/技能入口、选定问题编号及完整通过条件、相关文件与官方证据路径、允许修改的文件、已存在工作、复现方式和最小验证命令。不转发整段聊天、全仓文件或全部 16 项。`fork_turns: none` 时尤其要补齐必要上下文。
- 涉及连接恢复、会话作用域、FFI/线程或协议变化时，主代理先判断关键方案与不变量，再让 Luna 落地边界明确的修改。子代理超出文件范围前先向主代理说明；主代理可直接协调，不把常规实施选择转交给我确认。
- 子代理工作期间，主代理只做有价值的独立工作，例如准备官方对照、确认验收场景、检查未交给子代理的调用边界；不重复实现同一问题，不同时修改相同文件。官方连接和模拟器由主代理统一协调，禁止多个代理同时抢占。没有独立工作时等待结果，避免反复轮询。
- 子代理返回：根因与证据、修改文件及摘要、实际测试命令/结果、截图或日志路径、未验证风险。子代理的结论仅为“提交验收”，不得自行将全局验收表标为通过；测试之外不自行全量打包、安装、归档或更新多份状态文档。
- 主代理等待交付后亲自检查实际 diff，核对是否破坏已有修改；运行或复现本批最关键的验收场景，并亲自打开视觉/性能证据。子代理报告的证据与主代理复核的证据分别标明。对相同源码可复用已检查的测试日志，不机械再跑一遍全量测试；跨代理集成及主代理后续修改必须做相关验证。
- 主代理发现问题时，向原 Luna 发出具体失败场景和预期，优先复用同一子代理修正。本批连续两次修正仍无实质进展，主代理接管根因定位，必要时直接修复；不要无限换子代理或重复让它试错。接管后的改动仍须按同样条件验证。
- 只有主代理可更新本批最终状态并宣布验收通过。若缺少实际设备、官方对照或性能证据，保留对应待验证状态，即使 Luna 的单测全部通过也不升级结论。

### 逐项需求与通过条件

**01 搜索**：侧栏点击搜索后打开官方对应的搜索框体。核对搜索范围、数据源、匹配方式、结果分组、加载/空态、键盘焦点和结果跳转；仅把本地过滤框挪进弹窗不算搜索能力对齐。搜索结果选中后遵守第 04 项的导航语义。

**02 设备切换菜单**：以左下角触发按钮为定位锚点，根据可用空间决定弹出方向和限高滚动；移除与设备数量、窗口尺寸无关的固定偏移。少量/多量设备、横竖屏、大字号和安全区下都不越界、不遮挡关键入口。

**03 平板侧栏动画**：展开/收起有与官方依据一致的宽度或位移动画，右侧布局连续变化；支持快速反向操作及系统减少动画设置。开合不能重建会话、丢草稿、跳滚动位置。静态截图不能证明动画通过。

**04 会话切换**：宽屏/平板在当前工作区外壳内替换右侧聊天内容，侧栏保持稳定；不得每次点击都 push 一个完整聊天页面。A→B→A 验证标题、消息、草稿、滚动与选中态，快速切换时旧响应不能污染新会话。同设备跨工作区、跨设备切换明确作用域；窄屏返回行为单独验证，避免破坏既有导航。

**05 编辑工具的内联 diff**：编辑操作展开后显示可读的红删绿增、文件路径及必要上下文，而非仅展示 old_string/new_string 等原始参数。优先使用已确认的 patch/变更快照；只有 old/new 时计算真实文本差异，并说明可见范围，不伪造文件全文和行号。多次替换、重复文本、空文本、换行与截断必须有合理处理；原始参数可折叠保留。

**06 回合结束变更条**：查看 `references/assets/turn-change-summary-reference.png`。折叠态左侧依次排列展开箭头、文件数、绿色新增数、红色删除数；右侧按官方条件显示撤销，匹配边框、圆角、行高和间距。检查官方 changeSummary 数据如何到达聊天行，以及回合结束、历史加载、重连后是否正确显示且不重复。统计属于对应回合，不能用当前工作区总 diff 代替；没有变更时按官方门控处理，不强行每轮造一条。已有摘要组件和审查面板优先复用；撤销依赖真实能力及预检，验证使用合成服务。

**07 语音加载卡顿**：实测冷启动模型、再次录音、识别及取消过程，记录设备、模型、加载耗时和界面帧停顿。定位耗时调用所在线程/Isolate；异步函数里的同步 FFI 初始化或识别仍须检查。将阻塞工作移出 UI 执行路径，按平台支持选择实现，不能只加转圈动画。加载和识别时界面可响应、可取消，反复点击不重复初始化；切会话/退出后旧结果不得回填新输入框。

**08 未配置语音模型**：没有模型、已下载未启用、文件损坏、麦克风权限拒绝分别提供当前可见的提示与可执行入口。没有可用模型时可直接进入模型管理/下载；下载须由用户操作触发，不只把错误藏在 Tooltip 中。具备条件后可恢复语音输入。

**09 交互模式菜单**：逐项核对官方模式图标、标签、说明、排序、当前选中、禁用态、弹出位置和尺寸；不要所有模式共用一个图标。切换失败保留已确认配置与草稿。

**10 模型切换菜单**：核对供应商分组、模型排序/筛选、搜索或置顶等实际存在的能力、标签、选中态、尺寸及锚点；只实现有依据且远控适用的能力。模型和思考配置正确联动，切换会话或供应商后不串配置。

**11 底部终端**：对齐官方主区域底部抽屉、标签栏、会话名称、活动态、新建/关闭及高度行为。检查键盘弹出、滚动输出、输入、窗口 resize、中文 IME 和会话恢复。真实远端默认只读，命令与写操作用合成服务验证。

**12 右侧面板**：按官方可访问状态列出页签、工具入口、内容层级、展开/关闭、宽度与交互，逐一比对功能和样式。检查它与底部终端、主聊天和辅助聊天的独立性，以及窄屏覆盖形态；不能只用占位面板代替实际能力。

**13 设置中心设备管理与使用统计**：本提示词暂按“点击设置左栏后，在设置中心右侧直接展示内容”执行，避免只放一个按钮再打开独立页面。宽屏保留设置导航，窄屏按空间适配；设备/工作区数据隔离，返回后保留设置选择与浏览位置。如果我明确要求独立页面，则以我的说明覆盖本项，不同时建设两套无必要的流程。

**14 模型设置**：建立官方字段与操作对照，检查供应商列表/详情、连接方式、模型条目、默认配置、增删编辑、连接测试及实际适用的能力。核实远控门控、数据来源、保存/错误/回滚和对输入框模型目录的影响。先复用现有实现；缺协议依据的功能记录具体缺失字段或动作，不猜 RPC，也不把未知直接归为“不支持”。

**15 连接中断提示与恢复**：追踪 relay/bridge/工作区连接状态到当前可见界面的完整路径，区分首次连接、连接正常、意外中断、自动恢复中、恢复失败、配对/凭据失效和主动断开。不能仅用“设备对象仍存在”或“monitor 相同”代表连接正常。

- 连接层确认中断或降级后，当前聊天页和设置等受影响页面应显示可见状态与可执行的恢复入口，保留正在阅读的内容和草稿。提示形态优先对齐官方已确认行为；官方缺少对应状态证据时，明确作为本需求的恢复提示实现并保留视觉待验证。不要只在设备列表、日志或 Tooltip 里显示，也不要每次自动重试都弹模态框。
- 自动重连时显示“连接中断，正在重新连接”等准确状态；需手动操作时提供“重新连接/重试”，已知配对失效时提示重新配对。按当前状态提供取消/返回入口。按钮有防重复点击和进行中状态；成功后恢复正常展示，失败后保留原因和下一步，不能一直显示可用或无限转圈。
- 复用现有自动恢复机制，避免另起并行连接或用固定重试次数破坏既有恢复契约。主动断开不应被错误自动重连。恢复需完成有效握手、必要订阅和状态同步，不能只以 socket 已连上宣布会话恢复。
- 验证发送中断、重连期间操作、重复重试、重连中切换设备/会话、前后台恢复。保持草稿、历史与滚动；禁用不可用的远端操作并说明原因。已受理但回执不明的消息/命令应查状态，不自动重发；旧连接代次的迟到事件不得更新新来源。
- 使用合成服务/故障注入覆盖断网、心跳超时、远端退出、短暂掉线恢复、持续失败、凭据失效和主动断开，检查提示出现/更新/消失及操作结果。有可用设备时再补实际网络切换、休眠恢复验证；不为复现擅自终止真实远端进程或抢占正在使用的连接。

**16 设置中心全部适用页面的视觉与触发行为**：对官方目录和本地实际导航逐页盘点，包括常规、外观、模型/供应商、插件、技能、MCP、子智能体、命令、钩子、记忆、浏览器、索引库，以及本地的设备、统计、语音、通知等入口。以实际版本与门控为准，不把本地扩展冒充官方页面；第 13、14 项保留更具体的要求。

- 首次建立页面覆盖表：页面/入口、官方对应项及适用门控、视觉差异、行为差异、证据与状态。每页的按钮、开关、下拉、行点击、菜单、表单、链接等可交互控件都要有覆盖归属；按页面拆小批次，不能只抽查模型页后宣布设置中心完成。
- 本批页面逐控件记录“初始状态 → 操作 → 应出现的弹窗/面板/页面或修改 → 调用/数据作用域 → 成功及失败反馈 → 重新进入后的状态”。核对弹层与导航、字段/默认值、立即保存或显式提交、表单校验、取消与关闭、删除确认、加载/空态/禁用原因，以及是否真的执行了预期动作；纯动作按钮不要求保存状态，应验证其实际结果。
- 核对分组、布局、图标、间距、文案、选中态等视觉，同时检查是否错误新增跳页、错绑操作、仅显示成功提示却没有生效、失败后显示未确认值、刷新/重开丢配置。远端配置、设备配置与全局本地偏好分别验证作用域；断线/重连时联动第 15 项，旧响应不能覆盖新设备或新页面。
- 远端操作依据官方 UI 和已确认协议双向核对，写入使用合成服务；真实配置变更只在已有明确授权范围内执行。保存类功能需验证持久化与相关页面联动，不能只检查按钮可点或 RPC 返回成功。
- 主代理逐页验收后更新覆盖表；缺证据、未实现、仅合成通过、实际行为通过和视觉对齐分别标明。其余页面排入下一批，不得用“与官方大致一致”关闭整项。

### 实施与验证

- 优先修复共享组件或状态层，保持现有 Flutter / Dart / Kotlin 架构、主题 token 和已验证协议。路由、异步作用域、diff、语音问题按真实根因补回归；纯间距/颜色修改使用实际渲染对照，不为了增加测试数量写重复断言。
- 每批先运行最小相关测试；通过后做必要的静态检查与跨模块回归。原生改动实际编译验证；准备交付安装包时，再完成仓库要求的阶段检查、构建身份记录和安装验收。源码未变且无新疑点，不重复全量测试、打包、安装或归档。
- 视觉证据优先覆盖本批问题发生的视口，再检查一个关键手机/平板适配状态；按影响补深浅主题、字号和键盘状态。相同数据、视口及交互状态下并排打开官方与本地截图，实际检查差异。动画看连续帧/录屏，卡顿看运行性能，导航看连续操作。不要用单测通过、截图文件存在或包数量代替体验验收。
- 官方暂不可连接时，复用已冻结资产及历史有效证据，继续本地实现和合成验证。对未覆盖的真实链路保留“待验证”；不得宣称完整官方对齐。遇到相同外部失败且一次有依据的恢复尝试仍无变化，停止该路径，记录恢复条件，不反复截图、轮询或重扫不相关代码。
- 按上方分工执行“主代理 + Luna 实施子代理”。不要求额外输出内部推理，进度只报告新发现、关键决策与剩余事项。以实际可核实的主/子代理总用量、工具调用和返工评估费用，不能只算 Luna 单价就宣称整体便宜。
- 只增量更新现有验收表相关行与一个简短续接段；不要把相同长篇结论复制进多份文档。记录本轮新增问题、证据缺口、下一批入口，历史记录保留链接即可。

### 本轮结束时交付

1. 已修复的编号、根因和用户可见变化。
2. 实际运行的检查与结果，代表性前后截图/录屏/性能证据的位置。
3. 未通过项、具体阻塞与最小恢复条件；区分实现完成、合成验证、真实验证、视觉对齐。
