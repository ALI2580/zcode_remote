# ZcodeRemote 手机竖屏体验优化：可与性能专项并行的长程 Prompt

请执行 ZcodeRemote 的手机竖屏体验优化专项。当前另一个任务正在进行性能与代码结构优化；本任务需与它并行开发、分批集成，持续完成可实际使用的手机体验。中文沟通。直接实施，不只输出分析、设计建议或样式清单。

## 1. 目标、依据与本次设计授权

读取 `.agents/skills/project-cognition/SKILL.md` 和开发/测试规则，以及：

- `references/mobile-portrait-code-audit-2026-09-14.md`
- `references/optimization/master-todolist.md`、当前存在的性能/结构子清单
- `references/performance-optimization-execution-prompt.md`、`references/structure-optimization-execution-prompt.md`
- 最新 `references/ui-parity-current-todolist.md` 与相关验收项。

所有代码/行号/状态均重新核对。以 Android 手机竖屏、触屏操作为主，兼顾小窗口、横竖旋转和大字；不扩展成 iOS 原生专项。

本任务明确允许在手机上改变导航容器、菜单组织、信息层级、面板呈现和触控尺寸，解决直接压缩桌面布局的体验问题。官方协议、功能、字段、能力门控和业务确认语义不变；主题 token、图标和品牌延续现有体系。宽屏保持原有体验；手机的有意变化写入 mobile-design-decisions，不应被旧的桌面像素对齐要求强行回退，也不要标记为官方手机同态通过。

目标是“任务容易找到，主要操作容易点，内容易读，键盘不挡操作，返回路径可预测”，不仅是无 overflow。不要通过缩小字体/点击目标、全页横向滚动、删除功能、隐藏错误或锁死竖屏来通过测试。

## 2. 并行工作区与集成约定（M0，先完成）

先读 git status/diff、现有专项清单的 CURRENT BATCH/OWNED FILES。既有未提交修改、未跟踪模块和功能都是需要保留的输入；不要把它们算成本任务成果。

默认新建独立 worktree/隔离 checkout，分支使用 `codex/mobile-portrait-ux` 或不冲突的同前缀名称。若当前已在独立 worktree，核实后直接用它。性能任务继续在原目录工作。本 prompt 本身不要求另建更多任务、启动子代理或中断现有任务。

隔离副本必须来自完整且稳定的当前源码基线，而不只是旧 HEAD：

1. 优先采用现有任务已稳定的源码快照/已存在的提交。记录 HEAD 与 dirty manifest。
2. 若要包含 dirty 工作，保存并应用局部已审阅 patch；列出所需未跟踪产品/测试/资源文件，保持相对路径，包含它们的内容哈希。复制前后检查哈希/清单稳定性；变化则重取该批，不把混合时点当原子快照。
3. 不复制 `.git`、build 缓存、真实链接/凭据、签名私钥、设备数据、环境全集；`.dart_tool` 与依赖环境在副本重新生成。缺少可运行环境应准确报告并继续独立代码工作。
4. 如果无法得到稳定共享入口，先实现 mobile 独立组件、合成 fixture 与测试，等待稳定批次再接线；不能为了并行伪装“双方已锁定”。

所有权：

| 本任务优先拥有 | 性能/结构侧优先拥有 | 共享入口需逐批对接 |
| --- | --- | --- |
| `lib/ui/mobile/`、`test/ui/mobile/`、`integration_test/mobile_*.dart`、`references/mobile/` | `lib/protocol/`、缓存/索引/通知合并、业务 controller、语音 worker、性能基准、架构拆分 | shell_layout、workspace_shell、chat_page、settings_center_page 及新拆 settings 子页、composer、terminal_panel、review/code 展示组件、theme 与对应既有测试 |

移动端在独立 worktree 可修改共享入口，但每批保留最小接线 patch/API 要求，依据最新结构结果更新，不同时复制一整套旧业务实现。集成前对比 base/当前上游/本批三方改动，禁止整文件覆盖。

不编辑现有优化 master/performance/structure 清单，由各自 owner 维护。本任务维护独立日志，并提供 `references/mobile/integration-request.md`，列明 base、文件、接口、理由、已测内容、冲突与接入后应测内容。

若现有任务没有收到协作说明，不能单方声称它已暂停或让出文件。可以继续独立 worktree 中的实施；共享目录写回或设备占用需在明确的稳定窗口进行，整合未完成就保留待集成状态。现有授权允许本地集成时直接执行安全的局部集成，不额外要求无必要批准。

同一目录的 Flutter/Gradle 不并发；独立目录仍需注意共享 SDK、Gradle 和设备。不要杀掉他方进程、删除其锁/缓存或 force-stop 它正在验收的包。设备按任务分配；若只有一台，短时借用后交还，期间可继续桌面 widget 验证。独立 worktree 并不隔离 Android 包名和设备数据。

## 3. 先制定手机交互规则，再做一批可见实现（M1）

建立 `references/mobile/mobile-todolist.md` 与 `mobile-design-decisions.md`；每条有屏幕/状态、现状、目标、文件 owner、验收与证据。

按真实 LayoutBuilder 可用宽高、SafeArea、键盘和 TextScaler 决策，不能只用设备名称、Platform.isAndroid 或 orientation。允许建立 mobile 专用布局策略，默认以可用宽度不足 600 logical px 作为 compact 候选，但由内容与字号验证调整；保留 Composer 自身 384/576/672 断点，不用窗口宽代替其容器宽。

统一规则：手机独立交互目标至少 48×48 logical px，测实际命中区域与语义矩形而非图标大小；不重叠、不越父裁剪区。正文/表单字号从现有主题出发，支持系统大字；次要信息可以折叠，关键状态、来源与错误必须可理解。

第一轮在基线截图/流程核查后实现一个有真实收益的低冲突组件，例如触控操作按钮或移动端选择面板，并用合成宿主验证边缘命中、Back、键盘和大字。随后接入一个真实入口；入口正在重构时继续独立批次，记为待接线，不把孤立组件当功能完成。

## 4. 分批优化范围

### M2 项目/任务导航与聊天顶栏

- 设计手机任务入口，保留新建、搜索、最近任务、来源切换；高频动作可用拇指完成。评估可达的任务选择面板或专用列表，不能无依据增加常驻多标签底栏挤占聊天空间。
- 顶栏保留可辨认的任务标题、一个主要导航入口和有限主要操作；终端/Git/辅助面板等低频操作放有标签的更多菜单，当前激活状态仍可见。主/次操作列表由现有能力门控生成，不维护与桌面不一致的硬编码能力清单。
- 每个常用动作可见或有明确菜单路径；长按保留快捷入口，但不能是唯一发现方式。选择任务、长按菜单、关闭/删除不得互相误触。
- A→B→A、设备切换、搜索结果返回均保留草稿、阅读、标题与来源；不新建重复 route/连接/订阅来实现移动导航。

### M3 Composer、模型选择与键盘

- 发送/停止保持直接、足够大的目标与明确状态，单次点击不能重复发送。附件、语音、模型/模式按频率组织，次要配置可收进底部选择面板；避免一个窄 Row 塞满小 chip。
- 手机复杂模型/模式/引用选择使用适合搜索、滚动、选中状态和取消的底部面板或选择页；宽屏保留已有锚点弹层。复用同一个 controller/提交回调，避免形成双套业务状态。
- 短内容优先轻量面板，长表单/键盘搜索使用可扩展面板或完整页；遵守 SafeArea/viewInsets，标题、取消/关闭与主动作在键盘下可达，列表内部可滚动。
- 键盘开合、中文候选确认、长文本、多行、附件条、语音预览/错误同时出现时仍可输入和发送；键盘 inset 只应用一次。IME 确认不得误发送；失败不清空输入/附件。
- 增大目标后重新分配布局，不能给每个按钮简单加透明覆盖造成相邻误触，也不能扩大 Composer 到挤掉全部可读会话区域。

### M4 阅读、消息操作、代码与审查

- 长按/选择文本、复制、展开工具和消息操作在触屏上有可发现路径；复制不混入行号/按钮说明。链接、折叠箭头、更多入口保持足够目标。
- 保留虚拟列表、稳定 key/锚点和“真实滚动决定跟随”；新消息、面板开合和旋转不能把正在阅读的历史吸到底。
- 手机代码/diff 可提供换行切换、局部横向滚动或全屏阅读入口；页面整体不得随代码横滑。保持原文、差异语义、文本选择和辅助功能。
- 现有工作面板已能全宽覆盖，优先复用。完成文件列表→指定文件详情→列表→聊天的明确返回层级，保留列表位置/选中文件/聊天读位。不要压缩成难用的桌面三栏。
- 本任务不改高亮算法、缓存、会话分组算法；如发现性能问题，提交复现与指标给性能侧，视图层只做必要布局接线。

### M5 设置、设备、模型与目录

- 手机设置采用分类列表→详情，能理解当前分类与返回去向。直接打开某 section、深链接、重入和恢复都有确定路径，不强迫先经过下拉框。
- 复用结构侧新提取的页面/控制器。详情列表/编辑/确认有层级；返回未保存表单遵循已有草稿/确认契约；来源切换不把旧请求结果展示到新设备。
- 模型/供应商、MCP、插件、技能、命令、hooks、统计、通知、更新、语音和设备逐页登记。双栏管理器在手机按列表/详情适配，表单按字段组纵向排列，错误在当前可见位置展示。
- 设备配对/QR/引导若其他任务正改动，本任务只适配它们最新稳定接口；不重写二维码协议、权限流程或新增依赖。涉及凭据字段禁止写入截图和报告。
- 统计卡片按宽度换行，图表标注/明细通过触摸可用，筛选与来源可读；不以“移动端简化”为由删掉数据语义或把缺值补零。

### M6 终端、弹层与系统返回

- 核验竖屏终端的键盘后剩余高度；需要时增加最大化/全屏入口，保留已有 PTY，不因切换表现形式 create 新会话。
- 标签切换、关闭、复制粘贴、软键盘与必要快捷键可触控；验证中文输入字节与焦点。关闭终端/任务的语义保持原契约，不把 UI 返回等同于远端关闭操作。
- 返回按当前最上层处理：系统 IME 自身行为、当前弹层/选择页、面板详情、面板、设置/导航页、任务页。根据实际焦点与路由定义每个场景，而非全局强塞固定顺序；测试一次 Back 不触发两个 pop，预测返回取消不能产生导航副作用。
- 考虑系统手势边缘/底部区域、状态栏、横竖旋转、后台回来和 TalkBack 焦点。手势不是唯一入口，不与系统返回抢边缘。

## 5. 验收矩阵与真实证据（M7）

基线和优化后用同源码身份记录、同合成数据和同状态对照。主要手机尺寸（logical px）：320×568、360×640、390×844、412×915；补344×760旧回归点。覆盖键盘关闭/打开、深浅、中英、100%/140%，关键页面增加系统200%大字。全部主路径在390宽走通，小屏/大字对高风险组合成对覆盖，避免无意义全笛卡尔积。

宽屏非退化：720/834/1180，至少设置、聊天/Composer、审查与导航。边界宽度与旋转前后保证状态保留。不得以设备物理像素冒充 Flutter 逻辑像素。

测量并登记：

- 关键控件真实 rect、48×48命中测试（中心及靠边点击、相邻不误触）、语义标签/焦点顺序。
- 每个主流程点击路径和步骤数，常用动作原则上最多一次展开加一次选择；现有能力需要额外确认时保留并说明，不为少点一下取消必要确认。
- 键盘后可见输入区域、发送/提交/取消是否被遮、弹层是否越安全区、页面是否横向溢出、正文是否被不可滚动内容完全挤掉。
- 任务/设置/审查返回后的草稿、读位和来源；输入/弹层开关不增加业务请求与订阅。

主流程至少：找任务并切换返回、输入并选择模型后发送（假服务）、附件/语音与键盘、读历史并复制代码、打开 diff 并返回、进入设置编辑失败再重试（假服务）、打开终端输入与关闭表现层（假服务）。实际读回结果比只检查组件存在更重要。

复用已有 composer_ui、conversation_viewport、predictive_back、terminal_keyboard/drawer_constraints、settings_import_layout、settings_compact_switch_hit 等测试和 `review_capture.dart`，新增可观察的移动流程测试。辅助功能 guideline/几何检查不能替代真实点按；截图必须打开检查，记录前后 PNG 与短录屏。

组件/流转验证先最短集合，阶段完整 analyze/test/smoke。Android 原生变化实际编译。真机使用独立 QA 与合成服务，确认设备占用再安装；模拟器能证明布局与交互，不能冒称实体机单手体验、IME/系统手势全部通过。

性能侧基准冻结的宽屏场景维持原配置，本任务新增手机场景单独记账，不能改 fixture 掩盖性能回退。稳定集成前后由性能侧复测聊天/代码/来源关键基准；本任务测布局切换、滚动、键盘/面板的 profile 帧表现。没有设备性能结果就标待验，不把debug体感当达标。

## 6. 长程接续、集成与完成

独立清单头部记录：BASE SOURCE、CURRENT BATCH、OWNED FILES、UPSTREAM BATCH、INTEGRATION STATUS、LAST VERIFIED、BLOCKERS、NEXT EXECUTABLE。证据目录为 `build/mobile-portrait/<唯一批次>/`；版本漂移后注明哪些结果仍有效、哪些需要复验。

每批交付设计决策、真实实现、相关行为/截图、上游接口差异和下一步。做完一批继续下一项，不因某入口被结构侧占用而空等；先完成独立组件与其他页面。不循环轮询同一个阻塞，所有必需剩余项都受阻时明确保留未完成。

稳定批次集成顺序：对齐最新接口 → 三方审查/局部合并 → 相关行为/手机与宽屏渲染 → 联合性能非退化验证 → 更新本任务状态。工作区独立通过、已集成、集成后通过是三个不同状态。

完成门槛：所有 M0–M7 必需项已验证，主要路径可触控走通，已集成到目标源码，宽屏/协议/状态回归通过，性能侧收益未被回退，设备/系统验收有对应证据。必需项受阻只能宣布本地阶段通过，不把独立组件或截图集合当专项完成。

最终产出 `references/mobile/final-report.md`：前后主要变化、页面/状态覆盖、操作步骤与触控/布局数据、关键截图/录屏、最终源码身份、联合测试、集成状态与剩余条件。当前任务不自动获得提交/推送/发布授权；真实远端写操作按已有明确授权，未授权部分使用假服务。

现在从 M0 开始，完成首个可见且可验证的移动端批次，并持续接续。
